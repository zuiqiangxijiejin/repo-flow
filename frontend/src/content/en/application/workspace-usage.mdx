# Workspace Usage

The dark sidebar contains New chat, GitHub repositories, recent conversations and Settings. Collapsing it keeps an icon rail with hover descriptions. When the repository extension is loaded, SSH connections, repository settings and clone management open directly from the rail.

## Conversations and models

Choose **New chat**, associate your own project or a fork, and describe the task and verification steps. Repository conversations use separate workspaces and contribution branches while reusing the base clone where available.

The model selector sits on the right beside the mode and send controls. Full model names wrap. **Flash, Reasoning, Pro and Ultra** depend on model capabilities, account access and deployment settings. Thinking and planning are selected through the mode menu.

Send a message or use the attachment control to provide files. Reference available skills through the composer picker or `@`; manage and import skills under Settings → Optional features → Skills.

## Execution and results

Activity cards show actual tool calls. Read command output and regression records to assess verification. Generated files can be previewed or downloaded from the files and artifacts panels. Stored files and conversation history have separate lifecycles.

## Git review and publishing

Review the diff and verification results before publishing. **Save PR information** stores the destination, title and description in the app. Pushing a contribution branch uploads code to the contribution repository. Creating a GitHub draft or ready-for-review PR creates a real object in the selected target repository.

Use your own project directly with no upstream. For another project, choose your fork and its official upstream as the PR target. A draft PR is visible to the target repository's maintainers.

## Optional features

Settings → Optional features contains tools and integrations, skills and extension discovery, plus an entry for importing custom Agents. Subagents are created and edited in their separate settings section. Existing permissions and server capabilities govern each action.

Reopen stored conversations from the recent list. Deleting a conversation requires confirmation; inspect its associated data and files first.

See [Agents and Threads](/docs/application/agents-and-threads) and [Quick Start](/docs/application/quick-start).
