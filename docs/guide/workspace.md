# RepoFlow 工作区使用

默认输入区保持简洁。需要引用、语音或润色按钮时，在设置 → 外观启用“高级输入工具”。服务支持的浏览器控制、后台任务和子智能体批次入口按实际能力显示；第三方扩展动作仍使用扩展注册机制。记忆、通知、IM 渠道以及定时任务和用量页面统一从设置进入。

## 导航与对话

深色左侧栏包含新对话、GitHub 仓库、最近对话和设置。收起后保留图标栏，鼠标停留可查看操作说明。仓库扩展加载后，SSH 连接、仓库配置和克隆管理也可从图标栏直接打开。

点击已有仓库可在新对话中关联它。已有的基础克隆可复用；每个仓库对话使用独立的工作区和贡献分支，避免不同任务互相覆盖。克隆失败、目录不可写或仓库不可访问时按页面错误处理，无需反复创建新对话。

原对话的消息和运行事件保存在服务端。刷新页面不会把完整历史替换为当前加载窗口；删除对话则是单独的确认操作。

## 模型和模式

在输入框底部选择模型和模式。长名称会完整换行，底部控件会按空间重排。

| 模式 | 使用方式 |
| --- | --- |
| Flash | 直接完成简单任务，优先响应速度 |
| Reasoning | 使用模型可用的思考能力完成任务 |
| Pro | 先规划再执行，适合多步骤工作 |
| Ultra | 在 Pro 流程上使用可用的子智能体协作能力 |

模式是否可选取决于模型的能力和部署配置。并非每个模型都支持相同的思考参数；导入后应以能力识别、提示及实际请求结果为准。

## 仓库工具和执行位置

仓库按钮用于关联仓库与查看配置，附件按钮用于提供文件。对话顶部工具区显示本地执行或远程主机名称；SSH 连接用于管理自己的主机配置。

Agent 执行卡展示实际记录的工具调用。测试结果以工具输出和回归记录为依据；不会把“任务结束”自动当成“测试成功”。

## Git 审阅与发布

Git 审阅面板按检查改动、推送 Fork、创建 PR 展示实际状态。贡献分支、目标仓库与目标分支可展开查看；右侧面板宽度可调整。

发布区中的操作各自独立：

| 操作 | 结果 |
| --- | --- |
| 刷新改动 | 重新读取工作区状态并生成审阅信息 |
| 保存 PR 信息 | 保存应用内的目标、标题和说明，不创建 GitHub PR |
| 推送到我的 Fork | 把已审阅的提交推送到贡献仓库的分支 |
| 更正提交署名 | 通过确认流程修正提交作者，可能需要更新已推送提交 |
| 创建 GitHub 草稿 PR | 在目标仓库真实创建草稿，目标仓库维护者可见 |
| 创建 GitHub 正式 PR | 在目标仓库真实创建可供审阅的 PR |

按钮不能操作时会显示原因。已创建 PR 后继续推送同一个贡献分支会更新其代码；修改 PR 标题和说明应使用已有 PR 的 GitHub 编辑入口。草稿可以在 GitHub 标记为 Ready for review。

可使用“打开官方仓库 PR 表单”进入预填页面。链接说明存在长度限制；在应用内创建 PR 使用已保存的完整说明。见[仓库协作参考](repository-tasks.md)。

## 可选功能

打开设置 → 可选功能，按需查看工具集成、技能和扩展。普通工作区继续保持精简；权限、依赖和服务器尚未启用的能力会显示对应限制。详见[可选功能](optional-features.md)。
