# RepoFlow 运行维护

## 启停与访问

项目根目录下，`make dev` 启动开发服务，`make start` 构建并启动生产服务，`make stop` 停止服务。通过 nginx 的统一入口访问；默认端口为 2026。自定义端口以部署配置为准。

前端产物与代码扩展的静态文件都需要对应的发布步骤：修改前端后重新构建并重启前端，修改扩展后重启 Gateway 使其重新加载资源。不要在正在使用的发布目录中覆盖一半产物。

## 检查

```bash
make doctor
make check-agent-guidance
```

服务就绪可检查 Gateway 的 `/health/ready`。运行日志默认在 `logs/gateway.log` 和 `logs/frontend.log`，nginx 日志以部署设置为准。分享日志前删除凭据、Cookie 和用户内容。

## 备份与升级

升级前保存配置、运行数据和凭据加密所需的密钥。SQLite 运行中应使用数据库支持的备份方式，避免只复制主数据库文件而漏掉 WAL。恢复时，数据库、文件和密钥应来自一致的备份。

保留当前可运行的前端产物用于回滚。升级后检查登录、原有对话、模型列表、仓库配置和审阅页面，再使用新的发布目录。不要为测试真实推送或创建 PR。

`make clean` 会删除本地运行数据，包括账号、线程、上传、记忆和秘密；它不是只清缓存的命令，不适合日常维护。

## 分享源码

只提交源码、依赖清单、配置模板和项目文档。`.env` 及其环境变体、`config.yaml`、`extensions_config.json`、`.repoflow/`、`.deer-flow/`、`backend/sandbox/`、日志和个人自定义技能属于本地内容，不应上传。`.env.example` 保留为不含真实凭据的配置模板。

发布前检查待提交文件和内容；忽略规则不会移除已被 Git 跟踪的秘密。账号、对话、GitHub 授权、SSH 凭据及模型 API Key 随本地运行数据保存，不随源码分享。Git 提交署名可使用 GitHub 用户名和账号对应的隐私邮箱。

## 常见问题

| 现象 | 定位方式 |
| --- | --- |
| 网页一直加载或切换慢 | 检查 nginx、前端和 Gateway 是否就绪；生产使用构建产物；排查浏览器失败的请求 |
| 关联仓库后模型返回 422 | 检查供应商工具调用协议、消息顺序、思考参数和模型能力；保留脱敏错误供复现 |
| 模型或模式不可选 | 检查导入结果、账号可用模型和供应商支持的能力 |
| 仓库下载失败 | 检查仓库 URL、GitHub 授权、网络和克隆目录权限 |
| PR 按钮不可用 | 阅读旁边的状态说明，检查未保存目标、未推送提交或已有 PR |
| 对话看似缺少历史 | 确认账号与线程，检查历史分页和持久化状态；不要删除数据库来排错 |
| SSH 失败 | 在 SSH 主机设置验证地址、端口、用户名、认证与主机密钥确认 |
| 首次发布时 Skill Review CI 拦截已登记例外 | 首次提交没有可信基准，不能用本次提交中的例外批准自身；核实具体规则、文件哈希与例外后，后续提交才能从已有基准读取例外。不要关闭审查或加入个人 API Key 来消除告警 |
| 扩展 CI 提示找不到 pytest | 检查测试类型：Python 测试使用扩展的 `dev` 依赖和 pytest，浏览器 `.test.mjs` 测试使用 Node.js；浏览器测试包不应被强制安装 Python 测试工具 |

进一步参阅[部署参考](deployment.md)、[安全参考](security.md)和[服务拓扑](../agent-service-topology.md)。
